# cli: The stewards binary\: clap command parsing and dispatch, global flags (--human, --repo, -C, --direct), the JSON envelope and markdown output, CLI errors, and the shared test helpers.

## Overview

The cli unit is the stewards binary itself: the part a person or an agent actually runs. It parses the command line with clap, hands each subcommand to the unit that implements it, and makes every command answer in one predictable shape. By default a command prints a single JSON object on stdout, wrapped in an envelope that carries the stewards version and a schema number of 1 beside the command's own fields. With --human it prints the markdown rendering instead. When a command fails it prints the same envelope with an error holding a code, a message and a fix, and the process exits 2. The unit also owns the global flags (--human, --repo &lt;name>, -C &lt;dir>, --direct), validate (--report and --export), the forge seam (src/forge.rs) that posts a PR or MR comment through gh or glab, the tracker seam (src/tracker.rs) that files issues, and the shared test helpers.

## How it works

Everything starts in src/main.rs. Cli declares the four global flags, accepted before or after any subcommand, and a Command enum with one variant per subcommand. --help or --version prints clap's text and exits normally; any other parse failure is a CliError code usage, JSON unless --human is in argv, exit 2. After a good parse main builds a Global, changes directory for -C, and dispatch calls the owning module's run. completions and man print raw text (not enveloped). src/validate.rs runs validate --report: it records one JSON bug on the unit's card with the tester's bug checks, runs the repro through the allowlisted runner and writes the validator brief. validate --export calls tracker::export: every bug with a severity and no issue becomes one issue on the repo's [tracker] (github or gitlab through gh or glab api, jira or linear through ureq over https, no redirects), and its URL is written to the gap before the next issue; it stops at the first failure. Only text the tool composes is sent, in fences, and tokens never reach output, errors or files. src/review.rs runs stewards review: it records each --answer, keeps --task, reads up to 20 untracked result files, shows each as reported not verified, and lists due jobs unless findings or files remain; it removes the files once its output is written and exits 0 only when nothing is left. With --pr &lt;n> it posts that report as one PR/MR comment through forge::post; a failure sets pr_comment_error and never changes the exit code. src/forge.rs picks gh or glab from the origin host, passes --hostname and the repo path from origin, finds its own comment by author and marker and edits it in place, and caps the body at 65000 bytes. src/output.rs holds emit and CliError. Tests: tests/skeleton.rs, tests/forge.rs and tests/tracker.rs (fake CLI and fake HTTP), tests/review.rs, tests/validate.rs, helpers in tests/common/mod.rs.

## How to change it

To add or change a command, start in src/main.rs: add the variant and flags to Command, add its arm to dispatch, and put the work in a module declared in src/lib.rs whose run takes &amp;Global and returns anyhow::Result&lt;ExitCode>. Give the payload Serialize and Human implementations and print it with emit, so JSON and --human stay in step; do not write to stdout yourself (only completions and man print raw text, through write_stdout in src/completions.rs). Report failures as a CliError with a stable code and a concrete fix; main turns it into the envelope and exit 2. To post to a forge, call forge::post (or post_comment with the Fake CLI in tests); never read a PR title or body, keep userinfo out of messages, and report a post failure in the payload, not the exit code. To add a tracker, implement Issues in src/tracker.rs, route it in backend, keep every returned URL under issue_prefix, redact secrets from errors, and test it with FakeHttp. Keep true: one JSON object on stdout with the stewards version and schema 1; errors with code, message, fix, exit 2, JSON unless --human is in argv even for parse failures; --help and --version exit normally; global flags accepted anywhere; -C applied before dispatch; STEWARDS_DIRECT=1 equal to --direct. If the envelope shape changes in a way readers would notice, bump the schema number in output.rs. Check changes against tests/skeleton.rs and the other integration tests.
