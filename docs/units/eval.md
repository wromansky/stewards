# eval: The eval runner\: suites and their manifests, arm setup, the Pi driver and transcript parser, the ritual gate and overhead report, and the fixture, tasks and seeded-bug repros it runs on.

## Overview

The eval unit is the runner behind `stewards eval`. It measures whether coding agents do better with stewards than without: it drives a harness (Pi, Claude Code or Hermes Agent) over a suite of tasks in several arms, parses every session transcript into a run record, checks that the full arm followed the ritual, and reports cost and token overhead. The graders never branch on the harness. It also holds the material it runs on under evals/: the fixture, task prompts, suite manifests, arms.sh, and one reproduction per seeded bug.

## How it works

run (mod.rs) accepts pi, claude-code and hermes, picks arms, loads the suite (suite.rs, which checks each task's repro exists) and checks task numbers. pi.rs writes an isolated Pi agent dir; claude.rs a CLAUDE_CONFIG_DIR; hermes.rs a template home from which each session gets a fresh HERMES_HOME and whose gateway daemon is killed after it. Only pi takes --max-cost. execute reads every task prompt first, prepares the full arm once, then runs each task per run in every arm in a fresh copy. Each Driver starts a session (run_session, killing its group on timeout or on the one SIGINT/SIGTERM handler) and parses its transcript into a Run: tokens (null when unmeasurable, timed out or interrupted), cost, files opened (a listing never), stewards commands, subagent launches (a refused Hermes delegate is none), reviewer submits, a stored architect plan, models and thinking. After each session the runner runs `stewards next --no-brief --no-run` (full arms), runs the task's repro.sh with FIXTURE_ROOT set to the run directory (bug_fixed, every arm), records plan stored/closed on a task that expects_plan (full arm), and kills leftovers by cwd or HERMES_HOME. redact_secrets then replaces secret values (8+ chars) of each driver's credential_files with [redacted] in every kept session file and the run record. grade.rs grades each task on gate misses only; overhead ratios, bug_fixed and plan are report-only.

## How to change it

Start in src/eval/mod.rs for the command, the plan, shared session helpers, the interrupt handler and the per-session loop; pi.rs, claude.rs or hermes.rs for a harness and its transcripts; grade.rs for verdicts and the report; suite.rs for manifest fields. Tests live in tests/eval.rs (the interrupt test in tests/eval_interrupt.rs, its own binary), with recorded transcripts under tests/fixtures/transcripts/&lt;driver>/. Keep true: never write the user's harness config; bare and block-only arms never see stewards on PATH; overhead ratios, bug_fixed and plan stay report-only; graders never branch on the harness; one files-opened rule on every driver; no task prompt contains `think`; the first session always runs under --max-cost; no fixture holds key material; repro scripts take the fixture root from FIXTURE_ROOT. A new harness needs a Driver, a branch in run, and its entry in src/harness.rs.
