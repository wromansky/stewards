# cli: The stewards binary\: clap command parsing and dispatch, global flags (--human, --repo, -C, --direct), the JSON envelope and markdown output, CLI errors, and the shared test helpers.

## Overview

The cli unit is the stewards binary: it parses the command line with clap, hands each subcommand to the unit that implements it, and makes every command answer in one shape. By default a command prints one JSON object on stdout, an envelope carrying the stewards version and schema 1 beside the command's own fields; --human prints markdown instead. A failure prints the same envelope with an error holding code, message and fix, and exits 2. The unit owns the global flags (--human, --repo &lt;name>, -C &lt;dir>, --direct), the stub commands parsed but not built (validate --export, review --pr, next --pr, init --ci), and the shared test helpers.

## How it works

src/main.rs declares the Cli struct (four global flags, accepted anywhere) and a Command enum. --help and --version print clap's text and exit normally; any other parse failure is a CliError code usage, JSON unless --human is in argv, exit 2. main builds a Global (direct also from STEWARDS_DIRECT=1), enters the -C dir (failure is a usage error), and dispatch calls the owning module's run. completions and man print raw text on stdout with a save hint on stderr. src/validate.rs runs validate --report: it reads one JSON report (unit, title, repro, evidence, interface), applies the tester's bug checks, records the bug on the unit's card, runs the repro through the allowlisted runner and writes the validator brief with the result; a probable duplicate is reported and no brief is written; --export is not_implemented. src/review.rs runs review: it records --answer findings, keeps --task until review is done, reads up to 20 result files submit wrote, shows each as reported, lists due jobs unless findings or files remain, removes the files only after its output is written, and exits 0 only when nothing is left. src/output.rs holds emit (enveloped JSON or Human::render; a closed pipe is dropped quietly) and CliError (field errors serialised only when non-empty); any other error is code internal, exit 2. Tests: tests/skeleton.rs, tests/review.rs, tests/validate.rs, helpers in tests/common.

## How to change it

To add a command, add the variant and flags to Command in src/main.rs, its arm to dispatch, and the work to a module in src/lib.rs whose run takes &amp;Global and returns anyhow::Result&lt;ExitCode>. Give the payload Serialize and Human implementations and print it with emit; never write stdout yourself, since emit keeps a closed pipe from panicking (only completions and man print raw, through write_stdout). Return failures as a CliError with a stable code and a concrete fix; main turns it into the envelope and exit 2. To build a stub such as validate --export, replace its not_implemented call and add tests; the interface promises it fails with not_implemented until then. Keep true: one JSON object on stdout with version and schema 1 fields flattened with the payload; errors with code, message, fix, exit 2, JSON unless --human is in argv even for parse failures; --help and --version exiting normally; global flags accepted anywhere; -C applied before dispatch; STEWARDS_DIRECT=1 equal to --direct. Bump schema in output.rs if the envelope shape changes visibly. Check against tests/skeleton.rs and the other integration tests.
