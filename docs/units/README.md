# stewards

## Units

- [cli](cli.md): The stewards binary\: clap command parsing and dispatch, global flags (--human, --repo, -C, --direct), the JSON envelope and markdown output, CLI errors, and the shared test helpers.
- [model](model.md): The data model and its loading\: repo.toml and units.toml types (units, flows, decisions, roles, anchors), workspace and repo discovery, and the read-only user config and memory under \~/.stewards.
- [git](git.md): Thin wrapper over the git CLI\: tracked files, snapshot trees, ls-tree, object checks, and diffs between trees.
- [analysis](analysis.md): Read-only facts about the repo's files\: path-to-unit routing, anchor resolution and source windows, unit fingerprints and review stamps (check, stamp), and simplified\: debt scanning.
- [pack](pack.md): Builds a role's context pack within the byte budget\: unit summaries, anchors with source windows, owned files, and diff hunks; the pack command.
- [next](next.md): Workspace state reports\: status (units, freshness, coverage, gaps, debt) and next (which review jobs are due, optionally writing their briefs).
- [llm](llm.md): Role prompts and answer schemas\: baml\_src is their one source, rendered into src/llm\_schema; answer parsing through the generated types, and direct model calls.
- [jobs](jobs.md): The brief/submit job cycle\: renders and writes a role's brief with its header, validates the typed answer against it, writes the updates and retires the brief, and appends telemetry.
- [setup](setup.md): Onboarding and generated files\: init proposes units and writes .stewards, the guide and AGENTS.md block, the per-harness facts table, and docs rendering from unit cards.

## Decisions

- Docs fixtures route to setup through a narrower glob than model's tests/fixtures/\*\*: tests/fixtures/docs/\*\* only feeds the docs renderer tests, so setup lists it and the more specific glob wins routing; edits there review the unit that renders docs, not the model unit.
- Stewards adopts itself with checked-in .stewards cards and generated docs/units pages: Running the tool on its own repo exercises every role on real code; docs/units is rendered from cards so it stays in the repo as generated output, and the AGENTS.md block is the init-written one.
- A card patch upserts by key and removes only through explicit remove lists: A present list used to replace that whole part of the card, so a maintainer who sent the one interface it changed deleted the rest. interface, anchors, and gaps now upsert by id, path\:\:name, and title and keep every entry not named; remove\_interface, remove\_anchors, and remove\_gaps are the only removal, and each removal must name a key the card has and the patch does not also upsert, so a typo or a contradictory patch is rejected rather than silently dropping entries.
- Tester and documenter jobs wait for a unit's first stamp: Their marks live in the card's \[reviewed\] block and they measure from the stamp, so before the first maintainer review there is nothing to measure from and every file would look changed. A never-stamped unit gets its maintainer job first; a validator job for an unjudged bug does not wait, since it judges a reproduction, not a diff.
- The docs index is not part of the documenter's lost-update check: docs/units/README.md is rendered from every card, so documenters of two units in one round both rewrite it; refusing the second as a lost update would block a correct submit. The unit's card and its own page stay checked.
- A task's change has its own cap above the prose cap: A changes review joins every finding into one fix task, so with several findings the 2000-byte prose cap made a valid review impossible to submit. TASK\_CHANGE\_CAP (20000) applies to task changes only; other prose keeps the 2000 cap.
- A tester's bug takes the anchor of the interface it names: The anchor shows the validator where the bug is. A bug naming an interface takes that interface's anchor; one naming none keeps the anchor it had, and a repeated bug keeps its severity and issue so a tester's rerun does not undo the validator's judgment.
- Tester and documenter jobs trigger on an interface's lines, not its file: Maintainers record most public functions as interfaces, so a file trigger made a small edit in each of eight units cost 33 role jobs over two rounds. next\:\:interfaces\_touched now counts an interface only when a hunk of git\:\:diff\_hunks (mark to snapshot), on its old or new side or the line just before or after it, hits the interface's lines from anchors\:\:interface\_lines in that side's blob (git\:\:blob\_text). The line rule is a text block around each whole-word occurrence, for a fixed list of languages only; when the lines cannot be found (other language, name absent, file added or gone, mark tree pruned, blob unreadable) the file changing is enough. A change only in a private helper set apart by blank lines touches no interface; the maintainer's tester\_needed covers it. Shortcut until tree-sitter gives exact spans.
- Answer schemas state every length cap submit enforces: A model learned a cap only by being rejected; one review was lost to a 301-character contract. baml\_src stays the one source\: each capped field carries its cap there, rendered into src/llm\_schema, and the brief says an over-cap field is rejected. submit's cap constants stay the enforcement and are public so a test pins each constant to a schema field that states it, so the stated and enforced caps cannot drift.
