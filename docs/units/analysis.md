# analysis: Read-only facts about the repo's files\: path-to-unit routing, anchor resolution and source windows, unit fingerprints and review stamps (check, stamp), and simplified\: debt scanning.

## Overview

The analysis unit holds the read-only facts stewards derives from the repo's files. It answers which unit owns a path, whether a unit's anchors still point at real code, which lines an anchored interface spans, whether a unit's files have changed since its last review, and where `simplified:` debt comments sit. It never edits source: the one thing it writes is the review stamp on a unit's card. A reader meets it through `stewards route`, `stewards check` and `stewards debt`, and through the source windows and ownership answers that briefs are built from.

## How it works

Routing lives in src/route.rs. `owner` picks the unit whose glob matches most specifically (longest literal prefix, then fewest wildcards, ties by units.toml order), after normalizing ./ and backslashes. Paths under .stewards, the docs path and any .git component have no owner, ignoring ASCII case. `Router::overlaps` lists files two or more units match at equal top specificity. `stewards route` maps each path to its unit, repo-prefixed in a workspace, or to null. In src/anchors.rs, `resolve` finds the first case-sensitive whole-word match of the anchor's name: Found with a 1-based line, DeadName when nothing matches, DeadPath for absolute, ./.. , symlinked or unreadable paths, never panicking on invalid UTF-8. `source_window` returns that line with lines above and below, clamped to the file, or None for a dead anchor. `interface_lines(text, name)` returns the sorted 1-based lines of the block around every whole-word occurrence of the name (a qualified name also matches its last segment): down to a dedented line after a blank with brackets closed, up over the contiguous run plus one detached doc or attribute run. src/next.rs uses it to tell whether a diff hunk touches an interface. src/check.rs: `fingerprint` hashes the sorted `path blob` lines of the files a unit owns in the snapshot into `sha256:&lt;hex>`; a unit is stale with no [reviewed] stamp or a differing fingerprint. `stamp` writes [reviewed] to the unit's card, creating it if needed and keeping the rest. `check_at` produces the report: unreviewed, stale, dead_anchor and unknown_interface fail and `stewards check` exits 1; uncovered_interface, overlap, unowned (tracked files outside repo.toml's unowned_ok) and instructions_unlinked (a repo.toml instruction_files entry unreadable or not mentioning AGENTS.md) warn; a unit filter drops the last three. src/debt.rs `scan` lists `simplified:` comment lines from tracked, non-binary files outside .stewards, keyed by owning unit; `stewards debt` prints them per unit.

## How to change it

Start from the contract row for the function you touch (route-owner, route-overlaps, route-command, anchor-resolve, anchor-source-window, anchor-interface-lines, check-fingerprint, check-stamp, check-report, check-instructions, debt-scan) and its tests: tests/route.rs and tests/route_workspace.rs for routing, tests/anchors.rs, tests/check.rs and tests/debt.rs for the rest. Keep ownership consistent: the fingerprint, the overlap warning and the debt keys all rely on `owner`, so changing specificity or the no-owner paths shifts what counts as stale, overlapping or unowned. Keep the fingerprint over owned files in the snapshot, not the working tree. Keep `resolve` and `source_window` safe on bad input: a dead anchor, never a panic or a read outside the repo; instruction files go through Repo::read for the same reason. `interface_lines` is a text heuristic with a documented `simplified:` ceiling (Python triple-quoted strings, Rust raw strings); it feeds next's interface-touched decision, so a change to which lines a block covers changes which edits schedule reviewers; extend its tests in tests/anchors.rs. If you change which findings fail or warn, or how many a unit emits, update the check-report contract and exit code together; uncovered_interface stays one finding per unit. Keep the stamp merge in `reviewed_at`. Add a test next to the existing ones for new behavior.
