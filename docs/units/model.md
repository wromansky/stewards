# model: The data model and its loading\: repo.toml and units.toml types (units, flows, decisions, roles, anchors), workspace and repo discovery, and the read-only user config and memory under \~/.stewards.

## Overview

The model unit is how stewards learns what a repo says about itself and where it lives. It defines the types behind repo.toml and units.toml (units, flows, decisions, roles, anchors), finds the repo or workspace you are standing in, and reads the optional per-user config and memory under ~/.stewards. It is the one place that touches the .stewards/ directory on disk, so every other unit gets its repo data, and its safe file reads and writes, from here. The user config and memory are read-only: this unit never writes them.

## How it works

Loading starts in src/workspace.rs. discover looks for a stewards.toml at or above the cwd; one found wins over a nearer .git and lists the workspace's repos. Otherwise it takes the enclosing git root, or fails with not_a_git_repo. A repo without .stewards/repo.toml loads as None, and `only` narrows a workspace to one repo or fails with unknown_repo. current_repo picks the repo containing the cwd, else the lone repo, else not_in_repo. repo_containing gives the repo with the deepest root containing a path. loaded_repos pairs each repo with its Loaded, skipping uninitialized siblings in an unselected workspace (otherwise no_stewards_dir). Parsing is load_repo in src/model.rs: it reads .stewards/ under the git root, checks the schema version first (schema_too_new), then parses fully, reporting invalid_toml with file:line (also for a duplicate unit name). A missing units.toml, card or test card is fine. Anchor::parse splits `path::name` at the first `::`, both sides non-empty. Roles parse from six lowercase names, else unknown_role; Loaded::unit gives the unit or unknown_unit. All repo file access goes through safe_path: root/rel only when each part is a plain name and no existing component below root is a symlink, else unsafe_path. write renames a unique temp file over the target, so a planted link is replaced, never followed; it keeps permissions. append and remove act only on regular files and refuse symlinked paths; removing a missing file is Ok. In src/user.rs, load_config_from reads config.toml from $STEWARDS_HOME or ~/.stewards (missing is empty); Config::model(harness, role) returns the pinned alias or None. load_memory_from reads memory.toml [[entry]] items (missing is empty, malformed is invalid_toml with file:line). memory_for keeps entries matching the role and languages (absent means all), in file order, stopping before the first entry that pushes text past budget_bytes.

## How to change it

Start from the anchor for the behavior you want: load_repo or the type definitions for repo.toml and units.toml changes, discover and its neighbours for workspace and repo selection, and load_config_from, load_memory_from or memory_for for user data. Keep every repo read and write going through safe_path, which is the single path check; do not open files under .stewards/ any other way, and keep write replacing rather than following a symlink. Keep the schema_too_new check ahead of the full parse so a newer file gives that error instead of a confusing parse failure. Keep errors carrying file:line for invalid TOML, keep a missing units.toml, card or test card non-fatal, and keep the user config and memory read-only. Keep memory_for's truncation at the first entry over budget, not skipping to later smaller ones, and keep file order. The tests are tests/workspace.rs, tests/user.rs and tests/safety.rs, with inputs in tests/fixtures; add a case there for any new error or path rule, especially symlink cases in tests/safety.rs.
