# jobs: The brief/submit job cycle\: renders and writes a role's brief with its header, validates the typed answer against it, writes the updates and retires the brief, and appends telemetry.

## Overview

The jobs unit is the hand-off between the tool and the agent that does a piece of work. The tool writes a brief for one role on one unit (or for the architect, who has no unit), or one reviewer brief covering every unit a change touched, and gives the agent one sentence to pass to a subagent: Read `&lt;brief path>` and follow it. The agent answers in typed JSON, and submitting that answer checks it against the brief, writes the resulting updates, retires the brief, and leaves what it printed beside it as a result file for `stewards review` to collect. The brief carries the answer schema, with each field's length cap stated in it, and tells the agent that a field over its cap is rejected. Where the answer carries a card patch, submit also applies it to the unit's card: each list updates entries by key, and only the explicit remove lists delete. Each submit leaves one line of telemetry, so you can see how large the packs were and how many anchors agents had to open. It lives in src/brief.rs, src/submit.rs and src/telemetry.rs.

## How it works

Building a brief packs and frames a role's context (build in src/brief.rs; build_review for the reviewer, whose header lists its units and whose text asks the answer to copy its snapshot). It refuses an unsafe repo root (unsafe_path) and a validator brief with no unjudged bug (usage). rel_path names the brief .stewards/briefs/&lt;unit>-&lt;role>-&lt;snap>.md (architect-&lt;snap>.md, review-&lt;snap>.md, &lt;unit>-developer-&lt;n>-&lt;snap>.md), &lt;snap> the snapshot's first 8 hex characters, so a handoff from an older round names no file; job_of reads a name back, and write_text removes the job's briefs and answers at other snapshots. handoff turns the path into the one sentence; read_header parses the JSON header line, and a missing file or bad header is no_brief. Submit (submit_file in src/submit.rs) takes the brief the answer file's name gives, else the job's one brief (find), checks the header, then runs the role's handler. A field over its cap is answer_too_long with a target at 80% of the cap. A command in an answer must start with a commands.test entry or that unit's own test command (allowlist). check_patch validates a card patch before any write; apply_patch upserts, then applies the remove lists. The reviewer's handler runs the maintainer, tester and documenter checks per unit and writes nothing on any error. Writes go through write_remove_and_retire: it refuses link paths, returns card_changed if a checked file changed, writes in order, then removes the brief. src/telemetry.rs appends one JSON line of sizes and counts, and submit writes what it prints to the brief's .result.json; either failure only warns.

## How to change it

Start in src/brief.rs for what a brief says or where it lives, and in src/submit.rs for what an answer must satisfy or what a submit writes. Keep the header line format and the brief path scheme in step, because submit finds the brief by path and trusts the header to match. Build a job path only through rel_path, and its answer and result paths through answer_rel and result_rel. Give a subagent a brief only through handoff, and keep check_root refusing every character that could end or hide its code span. Print brief text only through emit. Keep the caps the schema states in step with the caps check_text enforces. Keep write_remove_and_retire checking for changed files and link paths before it writes, and the brief removal last, so a failed submit leaves the brief to retry. A check a role's handler makes belongs in a shared function the reviewer calls too, so a review answer is held to the same rules; review re-checks a result's findings with ShownFinding::passes_submit_checks, so keep it in step with what submit checks. For card patches, an entry leaves the card only by a remove list that check_patch has checked. Keep telemetry to sizes and counts, never content, and never let it or the result file fail a submit. The tests are tests/brief.rs, tests/submit.rs, tests/submit_roles.rs, tests/developer.rs and tests/review.rs; for a change to what a brief contains, assert on the rendered brief text.
