# stewards

## Units

- [cli](cli.md): The stewards binary\: clap command parsing and dispatch, global flags (--human, --repo, -C, --direct), the JSON envelope and markdown output, CLI errors, and the shared test helpers.
- [model](model.md): The data model and its loading\: repo.toml and units.toml types (units, flows, decisions, roles, anchors), workspace and repo discovery, and the read-only user config and memory under \~/.stewards.
- [git](git.md): Thin wrapper over the git CLI\: tracked files, snapshot trees, ls-tree, object checks, and diffs between trees.
- [analysis](analysis.md): Read-only facts about the repo's files\: path-to-unit routing, anchor resolution and source windows, unit fingerprints and review stamps (check, stamp), and simplified\: debt scanning.
- [pack](pack.md): Builds a role's context pack within the byte budget\: unit summaries, anchors with source windows, owned files, and diff hunks; the pack command.
- [next](next.md): Workspace state reports\: status (units, freshness, coverage, gaps, debt) and next (which review jobs are due, optionally writing their briefs).
- [llm](llm.md): Role prompts and answer schemas\: baml\_src is their one source, rendered into src/llm\_schema; answer parsing through the generated types, and direct model calls.
- [jobs](jobs.md): The brief/submit job cycle\: renders and writes a role's brief with its header, validates the typed answer against it, writes the updates and retires the brief, and appends telemetry.
- [setup](setup.md): Onboarding and generated files\: init proposes units and writes .stewards, the guide and AGENTS.md block, the per-harness facts table, and docs rendering from unit cards.

## Flows

- brief-submit-cycle: [jobs](jobs.md) → [pack](pack.md) → [llm](llm.md) → [model](model.md) → [git](git.md) → [analysis](analysis.md)
- next-job-scheduling: [next](next.md) → [analysis](analysis.md) → [git](git.md) → [model](model.md) → [jobs](jobs.md)
- documenter-card-to-docs-page: [jobs](jobs.md) → [setup](setup.md)

## Decisions

- Docs fixtures route to setup through a narrower glob than model's tests/fixtures/\*\*: tests/fixtures/docs/\*\* only feeds the docs renderer tests, so setup lists it and the more specific glob wins routing; edits there review the unit that renders docs, not the model unit.
- Stewards adopts itself with checked-in .stewards cards and generated docs/units pages: Running the tool on its own repo exercises every role on real code; docs/units is rendered from cards so it stays in the repo as generated output, and the AGENTS.md block is the init-written one.
