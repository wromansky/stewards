# next: Workspace state reports\: status (units, freshness, coverage, gaps, debt) and next (which review jobs are due, optionally writing their briefs).

## Overview

This unit answers two questions about a workspace: where do things stand, and what review work is due. `stewards status` prints one row per unit of every initialized repo: review freshness (fresh, stale, unreviewed), interfaces and how many a scenario covers, open gaps and bugs, debt, then a line saying what a stamp claims. Repos never initialized are listed apart. `stewards next` is the gate before reporting done. Plainly it lists, per repo, every stamped unit that is due in a reviewer job with its reasons (as many numbered review briefs as the budget needs), plus a maintainer first-review job per never-reviewed unit, and writes their briefs. `next --roles` lists the per-role jobs instead. It names changed files no unit owns and unowned_ok does not list. Unless --no-run, it also runs each open plan's step checks and each flow's check through the allowlisted runner, stores results, and closes a plan whose steps all pass on fresh units. With --pr &lt;n> it also posts the report as one PR/MR comment, updated in place. It exits 0 only when nothing is due, no such file is left, and the checks and plan and flow checks pass. A stamped unit stays due while a card anchor is dead. The tester and documenter fire on an interface's own lines changing. A never-reviewed unit gets only its maintainer job (and a validator job for an unjudged bug).

## How it works

`status` compares each unit's stored review fingerprint with a fresh one: no stamp is unreviewed, a match fresh, a mismatch stale; it counts interfaces, covered interfaces, gaps, bugs and debt, carries guide::STAMP_CLAIM, and always exits 0. `role_jobs` in src/next.rs snapshots each repo and builds per-role jobs per unit in fixed order: maintainer when stale or never reviewed, or when a stamped unit has a dead card anchor; tester and documenter when interfaces_touched finds an interface's lines hit by a diff hunk since the role's mark, or the whole file counts when anchors::interface_lines cannot place it; tester also on a changed test file, documenter also when needs_docs; both need a stamp. An unjudged bug gives a validator job. 2+ moved stamped units put an architect job first, unless an open plan of the repo has a step for every moved unit. `next` with roles writes each job's brief. Without, due_for_review folds stamped maintainer/tester/documenter jobs into one entry per unit, reviewer_jobs builds every review brief with brief::build_review, never-reviewed maintainer jobs follow; architect and validator jobs are dropped. changed_unowned fills NextReport.unowned_changed. With checks on, plan::plans_and_flows fills NextReport.plans and flow_checks; checks_failed is true when a flow check or step failed. review_due gives brief and pack the same due list. `run` with --pr renders the report without handoffs (NextReport::render_with(false), so no local path is posted), and forge::post in src/forge.rs finds this tool's own comment by marker and author and creates or edits it; the result goes in pr_comment, a failure in pr_comment_error, and neither changes the exit code. `run` exits 1 while any job, check failure, failed plan or flow check, or unowned changed file remains.

## How to change it

Change a due-job rule in the per-unit block of role_jobs in src/next.rs, and what counts as an interface change in interfaces_touched; plain next and review_due derive from role_jobs. Change which jobs the reviewer folds in due_for_review, keeping a never-reviewed maintainer job out of it. Keep tester and documenter jobs gated on a stamp. Take interface files through Anchor::parse. Keep the fallback: when interface_lines cannot locate an interface the file change still counts; tighten interface_lines, not next. Keep repo-prefixed names in the architect's list, and status freshness and next staleness on the same fingerprint. Keep the dead-anchor test the same as check's, and changed_unowned on the same unowned_ok and Router ownership as check. Plan and flow check running lives in src/plan.rs; next only calls it and reports. Keep the --pr text free of handoffs and local paths, and a posting failure out of the exit code; posting itself lives in src/forge.rs. Extend tests/next.rs, tests/review.rs, tests/status.rs and tests/plans.rs, and run them.
