# cli: The stewards binary\: clap command parsing and dispatch, global flags (--human, --repo, -C, --direct), the JSON envelope and markdown output, CLI errors, and the shared test helpers.

## Overview

The cli unit is the stewards binary itself: the part a person or an agent actually runs. It parses the command line with clap, hands each subcommand to the unit that implements it, and makes every command answer in one predictable shape. By default a command prints a single JSON object on stdout, wrapped in an envelope that carries the stewards version and a schema number of 1 beside the command's own fields. With --human it prints the markdown rendering instead. When a command fails it prints the same envelope with an error holding a code, a message and a fix, and the process exits 2. The unit also owns the global flags (--human, --repo &lt;name>, -C &lt;dir>, --direct), the stub commands that are parsed but not built yet, and the shared helpers the integration tests use.

## How it works

Everything starts in src/main.rs. The Cli struct declares the four global flags, accepted before or after any subcommand, and a Command enum with one variant per subcommand. --help or --version prints clap's text and exits normally; any other parse failure becomes a CliError with code usage, JSON unless --human is in argv, exit 2. After a good parse main builds a Global (human, repo, direct; direct also from STEWARDS_DIRECT=1), changes directory for -C (a directory it cannot enter is a usage error), and dispatch calls the owning module's run. completions, render and validate are stubs returning not_implemented; review --pr, init's unbuilt flags and next --pr reuse that helper. src/review.rs runs stewards review: it keeps --task in .stewards/briefs/review-task.txt until review is done, reads up to 20 untracked result files submit wrote, shows each as reported, not verified, and lists next's jobs with their handoffs unless a result reports findings or files are left. It removes the files only once its output is written, and exits 0 only when no job or check failure is left. src/output.rs holds the shared pieces. emit prints a payload as enveloped JSON or, with --human, through Human::render, and returns whether it was all written; a closed pipe is dropped quietly, other write errors go to stderr. CliError carries code, message, fix and, for a failed submit, field errors serialised only when non-empty. with_note appends a note to a CliError's message or adds context to any other error. A CliError from dispatch is emitted as is, any other error as code internal with fix 'report a bug'; both exit 2. Tests live in tests/skeleton.rs and tests/review.rs, with helpers in tests/common/mod.rs such as fixture, run and stewards.

## How to change it

To add or change a command, start in src/main.rs: add the variant and its flags to the Command enum, add its arm to dispatch, and put the work in a module declared in src/lib.rs whose run takes &amp;Global and returns anyhow::Result&lt;ExitCode>. Give the payload type Serialize and Human implementations and print it with emit, so that JSON and --human stay in step; do not write to stdout yourself, because emit is what keeps a closed pipe from panicking. Report failures by returning a CliError with a stable code and a concrete fix; the main loop turns it into the envelope and exit 2, so do not print errors or exit yourself. To build one of the stubs, replace its not_implemented call with a real run and add its tests; the interface promises those commands fail with not_implemented until then. Keep true the things callers depend on: one JSON object on stdout with the stewards version and schema 1 fields flattened with the payload; errors with code, message and fix, exit 2, and JSON unless --human is in argv even for parse failures; --help and --version exiting normally; global flags accepted anywhere on the line; -C applied before dispatch; and STEWARDS_DIRECT=1 equal to --direct. If the envelope shape changes in a way readers would notice, bump the schema number in output.rs. Check changes against tests/skeleton.rs and the other integration tests, which use the helpers in tests/common.
