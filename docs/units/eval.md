# eval: The eval runner\: suites and their manifests, arm setup, the Pi driver and transcript parser, the ritual gate and overhead report, and the fixture, tasks and seeded-bug repros it runs on.

## Overview

The eval unit is the runner behind `stewards eval`. It measures whether coding agents do better with stewards than without: it drives a harness (only Pi today) over a suite of tasks in several arms, parses every session transcript into a run record, checks that the full arm followed the ritual, and reports cost and token overhead. It also holds the material it runs on under evals/: the small three-language fixture, the task prompts, the suite manifests, arms.sh, and one reproduction per seeded bug.

## How it works

run (src/eval/mod.rs) accepts only the pi harness, picks the arms (bare, block-only and full by default; full-no-developers with --no-developers), loads the suite manifest from evals/suites/&lt;name>.toml (suite.rs, load) and checks the task numbers. A fixture suite copies evals/fixture; a repo suite clones the stewards repo at a pinned commit and builds it once. pi.rs finds pi and writes an isolated Pi agent dir with only pi-subagents, so the user's own Pi setup is never touched. execute then prepares the full arm once: for a fixture it runs arms.sh full, sets the hand-written units, and runs one adoption session with ADOPT_PROMPT; with --setup-dir it uses an already adopted copy; a repo suite is already adopted. Adoption must leave the fixture's code unchanged, every tracked file owned and `stewards next` clean, else eval_setup_incomplete. Each task then runs, per run, in every arm in a fresh copy; bare and block-only sessions get a PATH with stewards hidden. The Driver starts a session in a fresh environment and parses its transcript (pi.rs, parse) into a Run: tokens, cost, files opened, stewards commands and reviewer submits. After each session the runner runs `stewards next --no-brief` and kills leftover processes. grade.rs grades each task: an edit task passes only when every full run has no gate misses (it changed files, ran next, dispatched the review brief, a child submitted as reviewer, and next exits 0); overhead ratios are reported but never change the verdict. Results go to evals/results/&lt;timestamp>/ as runs/*.json, summary.json and summary.md; a session that would pass --max-cost is not started.

## How to change it

Start in src/eval/mod.rs for the command, the plan and the per-session loop; pi.rs for anything about Pi or its transcripts; grade.rs for verdicts and the report; suite.rs for manifest fields. Tests live in tests/eval.rs, with recorded Pi transcripts under tests/fixtures/transcripts/; add a transcript there when the parser must read a new shape. Keep true what the contracts promise: never write the user's Pi agent dir; bare and block-only arms never see stewards on PATH; a full arm that did not finish adoption is an error, not a quiet pass; overhead ratios stay report-only; the first session always runs under --max-cost. The transcript readers (stewards_commands, shell_reads) are best-effort, see the card's gaps before trusting a ritual miss. A new suite is a TOML file under evals/suites/ plus its task prompts; a new harness needs a Driver and its entry in src/harness.rs.
