# analysis: Read-only facts about the repo's files\: path-to-unit routing, anchor resolution and source windows, unit fingerprints and review stamps (check, stamp), and simplified\: debt scanning.

## Overview

The analysis unit holds the read-only facts stewards derives from the repo's files. It answers which unit owns a path, whether a unit's anchors still point at real code, whether a unit's files have changed since its last review, and where `simplified:` debt comments sit. It never edits source: the one thing it writes is the review stamp on a unit's card. A reader meets it through `stewards route`, `stewards check` and `stewards debt`, and through the source windows and ownership answers that briefs are built from.

## How it works

Routing lives in src/route.rs. `owner` picks the unit whose glob matches most specifically (longest literal prefix, then fewest wildcards, ties by units.toml order), after normalizing ./ and backslashes. Paths under .stewards, the docs path and .git have no owner. `Router::overlaps` lists files that two or more units match at equal top specificity. `stewards route` maps each path to its unit, repo-prefixed in a workspace, or to null. Anchors live in src/anchors.rs. `resolve` finds the first case-sensitive whole-word match of the anchor's name and returns Found with a 1-based line. It returns DeadName when nothing matches and DeadPath for absolute, ./.. , symlinked or unreadable paths, and it does not panic on invalid UTF-8. `source_window` returns that line with the requested lines above and below, clamped to the file, or None for a dead anchor. src/check.rs builds on both. `fingerprint` hashes the sorted `path blob` lines of the files the unit owns in the snapshot into `sha256:&lt;hex>`. Owned means the router gives the file to that unit, not merely that a glob matches. A unit is stale when it has no [reviewed] stamp or the fingerprint differs. `stamp` writes [reviewed] with commit, fingerprint, tree, tester and documenter to the unit's card, creating the card if needed and keeping the rest. A role left unmarked keeps the old stamp's tree. `check_at` produces the report. Unreviewed, stale, dead_anchor and unknown_interface are failures, and `stewards check` exits 1 on them. Uncovered_interface, overlap and unowned are warnings, with at most ten unowned files shown plus a count. A unit filter drops overlap and unowned. src/debt.rs `scan` collects `simplified:` lines, matched case-insensitively after a comment marker, from tracked regular non-binary files outside .stewards. It keys them by owning unit, with None for unowned files, and skips tracked files that were deleted. `stewards debt` prints them per unit.

## How to change it

Start from the contract rows for the function you touch (route-owner, route-overlaps, route-command, anchor-resolve, anchor-source-window, check-fingerprint, check-stamp, check-report, debt-scan) and its tests: tests/route.rs and tests/route_workspace.rs for routing, tests/anchors.rs, tests/check.rs and tests/debt.rs for the rest. Keep ownership consistent. The fingerprint, the overlap warning and the debt keys all rely on `owner`, so a change to specificity or to the no-owner paths shifts what counts as stale, overlapping or unowned. Keep the fingerprint over owned files in the snapshot, not the working tree. Keep `resolve` and `source_window` safe on bad input: absolute, dotted, symlinked, unreadable or non-UTF-8 files must yield a dead anchor, never a panic or a read outside the repo. If you change which findings are failures and which are warnings, update the check-report contract and the exit-code behavior together. Keep the stamp merge behavior, which preserves the rest of the card and an unmarked role's old tree. Add a test next to the existing ones for any new behavior.
