# dist: How stewards is shipped\: the release workflow, the install script, the AUR package, the release checklist, and the tests for completions, the man page and the install script.

## Overview

How stewards is shipped. A v&lt;x>.&lt;y>.&lt;z> tag runs .github/workflows/release.yml, which builds four archives (linux and macOS, x86_64 and aarch64), each holding the binary, the BAML library libbaml_cffi, shell completions and the man page. It then creates the GitHub release with SHA256SUMS and install.sh, runs cargo publish, and bumps the AUR package (not for prereleases). install.sh installs a release under ${STEWARDS_PREFIX:-$HOME/.local} after checking the tarball against SHA256SUMS. packaging/aur holds the PKGBUILD, .SRCINFO and bump.sh. RELEASING.md is the maintainer checklist and lists the known limits.

## How it works

Build job (per target): checks the tag, the Cargo.toml version and the `baml =` pin agree, builds, downloads libbaml_cffi from the BAML release and checks its sha256 against the matrix value, assembles bin/, lib/stewards/, share/ with the completions and man page generated by the freshly built binary, tars it and uploads it. Release job: requires four archives, writes SHA256SUMS, runs gh release create. Publish job: cargo publish with the registry token. AUR job: downloads the published .crate, runs bump.sh &lt;version> &lt;sha256> (rewrites pkgver, pkgrel=1 and the first sha256sums entry in PKGBUILD and .SRCINFO), and pushes both files to the AUR over ssh with a pinned host key. The binary finds the bundled library at &lt;exe dir>/../lib/stewards/ when BAML_LIBRARY_PATH is unset (prepare_baml_env in src/llm.rs). tests/completions.rs tests completions, man, install.sh (against a fake release served by curl and uname shims on PATH, no network) and bump.sh (two successive bumps on a temp copy of the AUR files).

## How to change it

Follow RELEASING.md in order. When baml is bumped, change BAML_VERSION and the four lib_sha256 values in release.yml and the version, URL and sha256 in PKGBUILD and .SRCINFO together; nothing checks the PKGBUILD side, and the bump.sh test hard-codes the PKGBUILD library sha256, so update it too. When an archive path or name changes, change release.yml, install.sh, the PKGBUILD package() and the FakeRelease fixture together. When PKGBUILD or .SRCINFO layout changes, bump.sh and its test change with it. The release workflow runs only on tags, so changes to it are not exercised before a release; cargo publish and the AUR push cannot be undone. Run cargo test for install.sh, bump.sh and completions; install.sh's tests need a non-musl host.

## Gaps

| gap | Release workflow is never exercised before a tag | The workflow runs only on v\* tags, and archive assembly, library checksums, gh release create, cargo publish and the AUR push have no dry run or pull-request check. A mistake surfaces on the real release, and cargo publish and the AUR push cannot be undone. |
| gap | Pinned BAML version is checked in the workflow but not in the PKGBUILD | The build job greps Cargo.toml for baml =\$BAML\_VERSION, but PKGBUILD \_bamlver, its library sha256 and .SRCINFO are only kept in line by hand (RELEASING.md step 1). They match today at 0.226.3 and can drift silently. |
| gap | install.sh test depends on the host not being musl | The uname shim fakes Linux x86\_64, but install.sh then runs ls /lib/ld-musl-\* on the real host, so the install tests fail on an Alpine machine. Only the Linux x86\_64 target branch is covered; macOS and aarch64 mapping and the musl refusal are not tested. |
| gap | AUR job resets pkgrel and the repo PKGBUILD never advances | bump.sh always writes pkgrel=1 and the job pushes only to the AUR, so main keeps the old pkgver. A manual pkgrel bump on the AUR is overwritten by the next release, and a re-run of the AUR job for the same tag is a no-op only if nothing else changed. |
| gap | SHA256SUMS shares a source with the archive | Already listed in RELEASING.md known limits\: the checksum catches corruption, not a tampered release. There is no signature or attestation. |
