# eval: The eval runner\: suites and their manifests, arm setup, the Pi driver and transcript parser, the ritual gate and overhead report, and the fixture, tasks and seeded-bug repros it runs on.

## Overview

The eval unit is the runner behind `stewards eval`. It measures whether coding agents do better with stewards than without: it drives a harness (Pi or Claude Code) over a suite of tasks in several arms, parses every session transcript into a run record, checks that the full arm followed the ritual, and reports cost and token overhead. The graders never branch on the harness. It also holds the material it runs on under evals/: the small three-language fixture, the task prompts, the suite manifests, arms.sh, and one reproduction per seeded bug.

## How it works

run (src/eval/mod.rs) accepts the pi and claude-code harnesses, picks the arms, loads the suite (suite.rs) and checks task numbers. pi.rs writes an isolated Pi agent dir; claude.rs an isolated CLAUDE_CONFIG_DIR with only the user's model and linked credentials. Claude Code runs at thinking off (MAX_THINKING_TOKENS removed) and refuses --max-cost, as its cost is not trusted. execute first reads every task prompt and refuses one containing `think`. It prepares the full arm once (arms.sh full plus an adoption session, --setup-dir, or a pre-adopted repo), then runs each task per run in every arm in a fresh copy; a driver's context_file (Claude Code's CLAUDE.md importing AGENTS.md) is folded into the last commit, and every commit has a neutral subject and author. Each Driver starts a session (run_session, killing its group on timeout) and parses its transcript into a Run: tokens (null when unmeasurable or timed out), cost, files opened per record cwd, stewards commands, subagent launches, reviewer submits, models and thinking. After each session the runner runs `stewards next --no-brief` and kills leftovers. grade.rs grades each task on gate misses only; overhead ratios are report-only; spent_usd is null when no run has a cost. Results go to evals/results/&lt;timestamp>/.

## How to change it

Start in src/eval/mod.rs for the command, the plan, shared session helpers and the per-session loop; pi.rs or claude.rs for a harness and its transcripts; grade.rs for verdicts and the report; suite.rs for manifest fields. Tests live in tests/eval.rs, with recorded transcripts under tests/fixtures/transcripts/ (claude-code/ holds session files plus stdout.log); add one when a parser must read a new shape. Keep true: never write the user's Pi or Claude Code config; bare and block-only arms never see stewards on PATH; unfinished adoption is an error; overhead ratios stay report-only; graders never branch on the harness; no task prompt contains `think`; commit subjects name nothing; the first session always runs under --max-cost; is_handoff accepts exactly what brief::handoff prints. A new harness needs a Driver, a branch in run, and its entry in src/harness.rs.
