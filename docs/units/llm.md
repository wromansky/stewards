# llm: Role prompts and answer schemas\: baml\_src is their one source, rendered into src/llm\_schema; answer parsing through the generated types, and direct model calls.

## Overview

The llm unit holds the role prompts and the answer schemas that the other units use to talk to a model. The prompts and schemas are written once, in baml_src, and rendered into src/llm_schema (a role text and a schema text per role). The unit gives callers three things: the prompt text for a role, the output-format description that tells a model what shape to answer in, and a strict parser that checks a reply against the role's answer type. It can also call a model directly, when a direct model is configured for a role.

## How it works

Role text and output format are read from the rendered files in src/llm_schema. role_text returns &lt;role>.role.txt with the `&lt;unit>` placeholder left for the caller to fill; only the maintainer distinguishes Review and Explain modes. output_format returns BAML's ctx.output_format text from &lt;role>.schema.txt, and non-maintainer roles ignore the mode. parse validates a reply through the types generated in src/baml_client: it accepts one JSON object with no surrounding text, no duplicate or unknown fields and snake_case enums. A failure is a FieldError carrying the field path, the problem and an example at that path. Parsing needs no BAML native library. The direct path is separate. prepare_baml_env is unsafe and must run before threads exist; it sets BAML_LIBRARY_DISABLE_DOWNLOAD unless STEWARDS_BAML_DOWNLOAD is set, sets BAML_LOG=off unless BAML_LOG is set, and removes every BOUNDARY_* variable. direct_guards then checks, in order, that [models.direct] for the role is &lt;provider>/&lt;model> with provider anthropic, openai or google-ai (else no_direct_model), that the provider's API key variable is non-blank (else no_api_key), and that the BAML native library loads (else baml_runtime_unavailable). It returns provider, model and key. direct calls the role's BAML function with a ClientRegistry client carrying that model and key, and returns the typed answer as JSON text. Any BAML error becomes the fixed direct_call_failed error, which never echoes the brief, the reply or the provider response.

## How to change it

Start in baml_src: change a prompt or an answer shape there, never in src/llm_schema or src/baml_client by hand, because those are generated. Then refresh: run baml-cli generate, then the ignored test llm::tests::refresh_llm_schema, which rewrites the rendered text and llm_sources.sha256. Keep the schema-freshness test in tests/llm.rs passing (generated_client_and_rendered_text_match_baml_src): src/baml_client must embed every baml_src file verbatim, llm_sources.sha256 must match baml_src/*.baml plus src/llm_schema/*.txt, and every generated enum must keep the on_generate snake_case rename. Keep parse strict and free of the BAML native library. Keep the guard order in direct_guards, keep prepare_baml_env called before threads exist, and keep direct_call_failed fixed so no brief, reply or provider output leaks into an error. Leave `&lt;unit>` in role text for the caller to fill.
